硬性架构约束

  • AI 只建议、不处置——写操作必须人工批准
  • 每次 LLM 调用必落 llm_calls（token/成本/耗时）
  • Agent 每步必落 ai_steps/ai_tool_calls，可回放
  • 所有写接口幂等（Idempotency-Key / 唯一键）
  • 配置缺失即启动失败，无默认密钥（fail fast）

// architecture / ai-internals

AI 调用链路 — Gateway · Agent · RAG

业务代码只依赖 LLMGateway 接口。左侧为调用链职责（每环可独立测试），右侧为 Agent 工具白名单与 RAG 管道。点击查看每环节的失败语义。

LLM Gateway 职责链

business → gateway.chat(request) → … → provider。任一环节失败都有确定性行为，绝无静默失败。
1 Model Router

按任务类型+能力+成本+健康度选模型：研判→强模型，嵌入/摘要→廉价模型（配置驱动）

▼
2 Budget Guard

单次调用/单次研判 token 预算检查，超限直接中止并标记，不烧钱

▼
3 Timeout

连接 5s / 总 60s（研判链 120s）→ 超时按失败处理进入重试

▼
4 Retry

指数退避+抖动 ×3，仅 429/5xx/网络错误；4xx 参数错误绝不重试

▼
5 Circuit Breaker

滑动窗口错误率>50% 熔断 60s → 直接走 fallback，防雪崩

▼
6 Provider Adapter

OpenAI / Anthropic / Gemini / Qwen / DeepSeek / Ollama / FakeLLM(测试)——统一协议转换

▼
7 Structured Output

JSON Schema Prompt + Pydantic 校验；失败携带校验错误重试 1 次；仍失败不落库

▼
8 Accounting & Observability

tokens/单价/成本落 llm_calls；trace span + 结构化日志；熔断/路由统计

告警研判 Agent（自研运行时，ADR-4）

ReAct 变体：计划 → 工具 → 观察 → 结论。max_steps=8 · token 预算 30k · 120s 超时 · 每步落库可回放。Agent 无任何写权限，危险动作只生成"建议"。
query_threat_intel(ioc)

本地 IOC 情报库查询：IP/域名/哈希信誉、标签、最后出现时间

query_asset(target)

资产库：IP/主机名的归属、重要性等级、负责人、暴露面

search_similar_alerts()

历史相似告警检索：结构特征 + 向量相似，返回历史结论分布

search_knowledge(query)

RAG 检索 Playbook/预案，返回带引用的 chunk

list_alert_context()

同一事件关联告警聚合视图（同主机/同时间窗）

propose_action(action)

生成"建议处置"（如封禁 IP）——仅记录，人工批准后执行

// architecture / stack & decisions

技术栈与架构决策记录（ADR）

每条决策均经过备选方案对比。完整理由见 docs/ARCHITECTURE.md 第 13 节。

层选型关键理由
后端Python 3.12 · FastAPI · Pydantic v2 · SQLAlchemy 2 · AlembicAI 生态最成熟；Pydantic 一份模型同时服务 API 校验与 LLM 结构化输出；原生异步适配流式
数据库PostgreSQL 16 + pgvector关系/JSONB/向量三合一，单库事务强一致，少一个有状态服务
缓存/队列Redis 7 · Celery限流/锁/broker 成熟组合，重试与定时任务开箱即用
前端React 18 · TS strict · Vite · Tailwind · TanStack Query · Zustand现代 SaaS 观感（非传统后台）；服务端状态与 UI 状态分离
AI自研 LLM Gateway · Agent 运行时 · pgvector RAG厂商可插拔、每步可审计可回放、成本可核算；不依赖 LangChain 重抽象
可观测structlog · OpenTelemetry · Prometheus/Grafana · Sentry(可选)request_id 全链路贯穿 HTTP→Celery→LLM
测试pytest · httpx · Playwright · FakeLLM确定性 AI 测试；权限/幂等/降级专项测试
部署Docker 多阶段 · Compose · GitHub Actions中小企业可运维的单机生产形态；迁移与回滚脚本化
ADR-1模块化单体

否决 微服务：1~5 人团队 + 单机运维，分布式成本>收益；模块边界（Service 接口 + 禁跨模块直连表）保住可拆分性。

ADR-2FastAPI + Pydantic v2

否决 Spring Boot / NestJS：AI 生态、异步流式、结构化输出与 API 校验同源。

ADR-3pgvector 单库

否决 Milvus/Qdrant 独立部署：知识库 ≤10⁵ chunks 远未到必要规模；单库事务保证业务+审计一致。

ADR-4自研 Agent 运行时

否决 LangChain/LangGraph：步骤有限（≤8）、每步必须审计落库，自研约 300 行完全可控可测。

ADR-5Celery + Redis

否决 ARQ/Dramatiq/RQ：企业认知度、重试/beat/监控生态最全。

ADR-6JWT + Refresh 轮换

否决 服务端 Session：无状态水平扩展；轮换+重用检测是 OWASP 推荐模式。

ADR-7显式状态机

否决 Temporal/Camunda：本期仅 3 条简单流；引擎部署与学习成本不成立，P2 Playbook 再评估。

ADR-8React+Tailwind 自建组件

否决 AntD/Element Plus：避免传统后台观感；shadcn 风格基础件完全可控。

ADR-9单机 Compose 生产

否决 K8s 优先：目标用户运维能力决定形态；K8s manifest 留作 P2。

ADR-10规则引擎降级

否决 硬依赖 LLM：安全运营系统不允许因外部 API 故障整体不可用；降级结果显式标记 degraded。
